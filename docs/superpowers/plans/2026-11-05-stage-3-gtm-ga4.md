# Stage 3 — GTM and GA4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Send the seven `tracking/events.yaml` events from the live site to a demo GA4 property through a generated GTM container, under Consent Mode v2 (advanced), verified offline, against real outgoing hits, and by hand in Preview and DebugView.

**Architecture:** A Python script turns `events.yaml` plus two public IDs into a GTM import file; offline tests pin the container to the contract and the site to the snippet. A live Playwright test captures and aborts real GA4 hits on the published site. Owner-run steps (accounts, import, publish, DebugView) are their own tasks with explicit checks.

**Tech Stack:** Plain HTML/JS site on GitHub Pages, Python 3.13 with PyYAML, pytest + pytest-playwright via `uv run pytest`, Google Tag Manager (Web), GA4.

**Spec:** `docs/superpowers/specs/2026-11-05-stage-3-gtm-ga4-design.md`

## Global Constraints

- Code, comments, docs and commit messages in English; commits `type: short description`, one change per commit, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Event and parameter names come only from `tracking/events.yaml`; no hand-typed names in the container.
- The default `uv run pytest` run never reaches Google: Playwright aborts requests to `googletagmanager.com` and `google-analytics.com`. Live tests are marked `live` and excluded by default.
- The consent default and the re-applied saved choice stay inline in `<head>`, before the GTM snippet. The `GTM slot` marker comment stays in place (existing tests use it).
- `tracking/gtm/ids.yaml` holds only public IDs; nothing from `.private-terms` in any tracked file (enforced by the existing leak test).
- Nothing reaches GA4 from tests: the live test aborts every `/g/collect` request it captures.
- QA (Tasks 6–7) finishes before stage 4's simulator starts.

## Review Focus

- **Batched GA4 hits:** gtag.js often sends several events in one POST, shared params in the URL and one line per event in the body. The hit parser must return one dict per event → Task 5 test `test_parse_batched_body`.
- **Location restored from the URL before the list exists:** options are built asynchronously from `schools.json`; restoring `?location=Austin%2C+TX` must wait for them and end with that option selected → Task 2 test `test_location_restored_from_url`.
- **Unknown location in the URL** (`?location=tx`, an old free-text link): treated as "Any location", and a later search pushes no `location` → Task 2 test `test_unknown_location_is_ignored`.
- **Enhanced measurement duplicating `view_search_results`** if "Site search" is left on: the live test asserts exactly one `view_search_results` hit per search → Task 5 test `test_live_granted_journey`.
- **Container drift after an `events.yaml` change:** a new parameter must produce its variable and appear on its tag → Task 4 test `test_new_param_flows_into_container`.

**Interfaces:**

Run as `uv run python -m scripts.make_gtm_container`.

Container shape (GTM export format; the field names are GTM's, not a choice):

```text
{"exportFormatVersion": 2, "containerVersion": {
  "tag": [
    {"tagId": .., "name": "Google tag", "type": "googtag",
     "parameter": [{"type": "TEMPLATE", "key": "tagId", "value": <G-…>}],
     "firingTriggerId": ["2147479573"]},                       # built-in Initialization - All Pages
    {"tagId": .., "name": "GA4 event - <event>", "type": "gaawe",
     "parameter": [{"type": "TEMPLATE", "key": "eventName", "value": <event>},
                   {"type": "TEMPLATE", "key": "measurementIdOverride", "value": <G-…>},
                   {"type": "LIST", "key": "eventSettingsTable", "list": [
                     {"type": "MAP", "map": [{"type": "TEMPLATE", "key": "parameter", "value": <param>},
                                             {"type": "TEMPLATE", "key": "parameterValue", "value": "{{dlv - <param>}}"}]}, ...]}],
     "firingTriggerId": [<trigger id of ce - <event>>]}, ...],
  "trigger": [{"triggerId": .., "name": "ce - <event>", "type": "CUSTOM_EVENT",
               "customEventFilter": [{"type": "EQUALS", "parameter": [
                 {"type": "TEMPLATE", "key": "arg0", "value": "{{_event}}"},
                 {"type": "TEMPLATE", "key": "arg1", "value": <event>}]}]}, ...],
  "variable": [{"variableId": .., "name": "dlv - <param>", "type": "v", "parameter": [
                 {"type": "INTEGER", "key": "dataLayerVersion", "value": "2"},
                 {"type": "BOOLEAN", "key": "setDefaultValue", "value": "false"},
                 {"type": "TEMPLATE", "key": "name", "value": <param>}]}, ...]}}
```

IDs are strings of consecutive integers assigned in `events.yaml` order (variables in first-appearance order of their parameter), so output is deterministic. Each event's tag lists exactly that event's params in YAML order, `experiment_variant` included where the YAML has it. Also set `accountId` and `containerId` to `"0"` on the version and on every item; if the GTM import in Task 6 rejects the file, fix the shape here and re-run Task 4's tests.
