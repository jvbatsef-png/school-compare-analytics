# Stage 2 — Site and dataLayer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A static school-search site whose every interaction produces the `dataLayer.push` defined in `tracking/events.yaml`, verified by Playwright and published on GitHub Pages.

**Architecture:** Three plain HTML pages under `site/` share small classic scripts that hang off one global namespace `window.SCA`. Only `track.js` writes to `window.dataLayer`. Python Playwright tests serve `site/` from a local thread and validate every push against `events.yaml` through `tracking.spec.load_spec`.

**Tech Stack:** HTML, CSS, vanilla JavaScript (no build), Python 3.13, pytest, pytest-playwright (Chromium), GitHub Actions Pages deploy.

**Spec:** `docs/superpowers/specs/2026-11-05-stage-2-site-design.md` (parent: `docs/superpowers/specs/2026-11-05-school-compare-analytics-design.md`).

## Global Constraints

- Event names, parameter names and consent defaults come only from `tracking/events.yaml`; never hard-code a second copy in Python tests (read it via `load_spec`).
- `window.dataLayer` is written only by `SCA.track` and by `gtag()` (consent commands).
- No value typed by the visitor in the "Request info" form ever reaches the dataLayer.
- Optional event parameters with no value are omitted, never sent as `""`, `null` or `undefined`.
- Storage keys: `sca_variant` (`"A"` or `"B"`), `sca_consent` (`"granted"` or `"denied"`). Variant draw: `Math.random() < 0.5 ? "A" : "B"`.
- Compare tray max 3 schools; comparison needs at least 2.
- `source` values: `results`, `compare`, `direct`. `lead_type` is always `info_request`.
- Repository content in English; no personal context (enforced by `test_repo_has_no_personal_context`).
- Visual style: clean, neutral, minimal; system fonts; one stylesheet; no images.
- Commits: `type: short description`, one change per commit, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.
- Tests: `uv run pytest -v` (all 20 stage 1 tests keep passing).

## Review Focus

1. Search with zero matches → empty-state message; `view_search_results` still fires with `results_count: 0` (test in Task 3).
2. Search with empty optional fields → those keys are absent from `search` and `view_search_results` (test in Task 3).
3. Profile URL with a missing or unknown `id` → "School not found" message, no `school_profile_view` (test in Task 5).
4. Stored variant is corrupt (`"C"`) → a fresh draw replaces it (test in Task 2).
5. `localStorage` throws (blocked storage) → the page still works with an in-memory variant and consent, and no script error (test in Task 2).

### Task 2: Page shell, variant, tracking and consent

**Files:**
- Create: `site/index.html` (shell only: head, banner container, empty `<main>`), `site/js/experiment.js`, `site/js/track.js`, `site/js/consent.js`, `site/css/style.css` (base layout + banner), `tests/test_site_core.py`

**Interfaces:**
- Consumes: `open_page`, `pushes`, `events_named`, `assert_valid` (Task 1).
- Produces (JS, all on `window.SCA`):
  - `SCA.getVariant(): "A" | "B"`; invalid or missing stored value → draw and store; storage error → draw once and keep it in memory for the page.
  - `SCA.track(event: string, params: object): void`; adds `experiment_variant: SCA.getVariant()` unless `event === "consent_update"`; drops keys whose value is `undefined`, `null` or `""`; pushes `{event, ...params}`.
  - `SCA.consent.save(state: "granted" | "denied"): void`; `gtag('consent','update', {analytics_storage: state, ad_storage: state, ad_user_data: state, ad_personalization: state})`, stores `sca_consent`, hides banner, then `SCA.track('consent_update', {analytics_storage: state, ad_storage: state})`. On load, a stored choice is re-applied with `gtag('consent','update', …)` and no event; no stored choice → banner shown.
  - Banner buttons: `#consent-accept`, `#consent-reject`; link to `privacy.html`. The banner is a bottom bar that does not cover the page content.
  - Head order in every page: (1) inline script defining `window.dataLayer = window.dataLayer || []`, `function gtag(){dataLayer.push(arguments);}`, `gtag('consent','default', {...four denied values})`; (2) the comment `<!-- GTM slot: container snippet goes here in stage 3 -->`; (3) site `<script src>` tags in order `experiment.js`, `track.js`, `consent.js`, then page scripts, all with `defer`.
